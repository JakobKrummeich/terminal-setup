Make the quiz phase actually playable end to end, as a vertical slice through every layer.

Participants must be able to answer the current quiz question exactly once, the server must keep a
live tally per answer option, and both the presenter and the participant screens must reflect it:

- The quiz content that already ships with the repository as configuration must be loaded and
  validated at startup instead of being ignored, and served to clients for the current question in
  both supported languages.
- A participant intent for casting an answer, routed the same way the existing facilitator intent
  is routed, persisted, and broadcast as new state. A second answer from the same participant for
  the same question is rejected through the existing rejection mechanism, not by crashing.
- Tallies per answer option in the pushed state, correct after reconnects, with no way for a client
  to learn who voted for what.
- Participant screen: the current question with one button per answer, disabled once answered, and
  the correct answer marked after the facilitator has revealed it.
- Presenter screen: the live tally per answer, updating as votes arrive.

Acceptance criteria:
- Follow the architecture, naming and layering rules of this repository exactly, including how
  intents, rejections, persistence and pushed state are already done for the existing intent.
- Add tests at the layers this repository tests at, including the rejection paths and the config
  validation.
- The existing test suites, the type check, and any coverage or duplication gate still pass.
