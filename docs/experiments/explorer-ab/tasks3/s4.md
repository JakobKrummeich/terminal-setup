Implement group formation as a vertical slice through every layer, without any solver dependency.

When the workshop enters the group phase, the server splits the participants into groups, gives
each group a name and a set of values to work on, persists the result, and every screen shows it.

- Group count and sizes follow the sizing rule documented in this repository's planning material;
  derive them from it rather than inventing your own, and handle the small-N edge cases it names.
- Groups get their names from the name catalogue that already ships as configuration, which must be
  loaded and validated at startup instead of being ignored, and must not run out or repeat.
- Values are dealt out over the groups deterministically, preferring, for each participant, a group
  whose values overlap that participant's own selection. A simple deterministic assignment is
  expected — no optimisation library, no randomness that would make a restart produce a different
  split.
- Formation happens on phase entry, is persisted, and a restart reproduces exactly the same groups.
  A participant joining late is placed by the mechanism the domain already has for that.
- Participant screen: own group, its members and its values. Facilitator screen: all groups with
  their members and values.

Acceptance criteria:
- Follow the architecture, naming and layering rules of this repository exactly, including how
  phase entry, persistence and pushed state are already done.
- Add tests at the layers this repository tests at, including the sizing rule with the edge cases
  named in the planning material and the restart-reproducibility property.
- The existing test suites, the type check, and any coverage or duplication gate still pass.
