Implement the value selection phase as a vertical slice through every layer.

Each participant picks exactly ten distinct values from the catalogue that already ships with the
repository as configuration, and submits them once; the facilitator watches submissions come in.

- Load and validate the value catalogue at startup instead of ignoring it, and serve it to clients
  in both supported languages.
- A participant intent for submitting a selection, routed and persisted the way the existing
  facilitator intent is, with server-side enforcement: fewer or more than ten, duplicates, unknown
  values, or a second submission from the same participant are all rejected through the existing
  rejection mechanism.
- A submitted selection locks in: it is persisted, survives a restart, and is reflected in the
  pushed state.
- Facilitator screen: a live count of how many participants have submitted out of how many joined.
- Participant screen: the catalogue with selectable entries, a visible count of how many are still
  to pick, a submit control that is only enabled at exactly ten, and a locked-in view afterwards.

Acceptance criteria:
- Follow the architecture, naming and layering rules of this repository exactly, including how
  intents, rejections, persistence and pushed state are already done for the existing intent.
- Add tests at the layers this repository tests at, including every rejection path and the
  config validation.
- The existing test suites, the type check, and any coverage or duplication gate still pass.
