When a branch touches generated or vendored files (lockfiles, build output, snapshots), they flood the review and waste the model's grouping budget.

Add a repeatable command-line option on the command that opens a review that drops matching paths from the extracted change set, plus an equivalent persistent setting in the per-repository config file so a team doesn't retype it; patterns are simple globs matched against repo-relative paths, and the command line adds to the config rather than replacing it. Excluded files must not reach the model, must not appear in the reviewed file list or its counters, and the review output must state how many files were excluded so nothing silently disappears. Reject an option value that is empty, and fail cleanly if every file was excluded. Do not add a new dependency.

Acceptance criteria:
- The existing test suite still passes (`npm test`, 1112 tests).
- New tests cover glob matching, counter consistency, and the all-excluded case.
- The change fits the conventions already used in this codebase.
