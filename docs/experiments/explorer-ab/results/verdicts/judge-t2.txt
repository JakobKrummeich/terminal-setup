reasoning: Both wire the flag plus a config `exclude` key, merge (not replace), recompute `diffStats` from kept files, report the excluded count, reject empty patterns, throw a new `diff_all_excluded`, and add no dependency. The glob engines differ materially: solution-1 matches segment-by-segment with a true `**` that spans zero or more segments, so `src/**/*.snap` catches `src/page.snap`, while solution-2 compiles `**` to `.*` and special-cases only a leading `**/` — so `test/**/*.snap` silently misses `test/a.snap`, a silent keep in exactly the case the feature exists for, and it is neither documented nor tested. Solution-1 also trims config patterns and names the offending index (`exclude[1]`) for non-strings; solution-2 skips the trim in config, so `" dist/**"` is accepted and matches nothing. Solution-1's table-driven glob tests are broader (metacharacters, anchoring, basename rule, kept+excluded invariant), and it keeps `excludes` as a distinct `StartInput` field rather than solution-2's stuffing CLI values into the loaded `config` object. Solution-2 is better in two places: it updates `spec.md`, which solution-1 leaves stale on both the flag and the config key, and its CLI test drives a real git repo end-to-end to prove config+flag union and `diff_all_excluded` exit 1. Those wins are real but do not outweigh a wildcard that quietly under-matches.
